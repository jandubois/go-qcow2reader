Executive Summary ¶

PR 77 adds a dynamic VHDX writer and a convert -O vhdx option. The encoding holds up: qemu-img reads the output back identical to the source, CI passes at the review SHA, and a reviewer booted a converted image under Windows HCS. Five Important findings remain. The README example finalizes a failed conversion, invalid conversion options still destroy an existing target, two writer paths have no test, and two comments misstate hole behavior and the BAT size.

Four reviewers ran against 65fefc6. Codex's first launch failed on an expired login and ran again after re-authentication. Every finding below was checked against the code, and each Important one carries a reproducer run from this report at the review SHA, with its fix applied and the reproducer run again. Copilot's two comments on an earlier revision are both resolved here: the CLI validates the output format and block size before os.Create, and the Writer doc says a block is never deallocated.

## Limitations

The following features are not supported yet:

The example discards the conversion error and calls Close anyway. Close writes the BAT and then the file type identifier (image/vhdx/writer.go:452-454), and writing the identifier last is what keeps an interrupted conversion from being detected as a VHDX. Code that follows the example turns a failed conversion into an image qemu-img opens without complaint, with the unconverted half reading as zeros. The README's first example also drops errors, but there a missed error ends in a nil-pointer panic; here it ends in a quietly wrong disk.

// tools (typically 8 MiB to 32 MiB), since the unwritten part of a partially
// written block is allocated by file systems that do not support sparse
// files, or that fill small holes.
func DefaultBlockSize(size int64) int64 {
	blockSize := MinBlockSize
	for blockSize < MaxBlockSize && size > blockSize<<20 {
		blockSize <<= 1
	}
	return blockSize
}

Design Observations ¶

Concerns

  • Close finalizes whatever was written (future) Codex GPT 5.6 Sol — writing the file type identifier last protects an interrupted conversion only while nothing calls Close, and a deferred Close, the usual Go idiom, finalizes a failed one (I1). An explicit finalize step, with Close only releasing resources, would make the safe path the easy one.
  • The CLI's target setup is not transactional (future) Codex GPT 5.6 Sol — validation, truncation, conversion and finalization are spread through cmdConvert. Converting into a temporary file beside the target and renaming it on success would cover I2, S2 and a failure mid-conversion in one change.

Strengths

  • Unwritten blocks get PAYLOAD_BLOCK_ZERO (in-scope) Claude Opus 5 — line 594. MS-VHDX 2.5.1.1 leaves PAYLOAD_BLOCK_NOT_PRESENT undefined in a dynamic image and requires zeros for PAYLOAD_BLOCK_ZERO, so skipping zero writes is safe for any reader, not only qemu.
  • The file type identifier goes out last (in-scope) Claude Opus 5 Codex GPT 5.6 Sol — lines 452-454. A conversion that stops early leaves a file no reader takes for a VHDX, as the second run in I1's probe shows.
  • Output-format and block-size checks run before os.Create (in-scope) Claude Opus 5 Codex GPT 5.6 Sol — an invalid -O or -block-size leaves an existing target intact (run), which resolves Copilot's comment on the earlier revision.
  • The zero scan runs outside the mutex (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.1 Pro Gemini 3.5 Flash — lines 389-402. Payload writes proceed in parallel, and the re-check under the lock keeps two goroutines from allocating one block (I3 asks for a test of it).

Acknowledged Limitations ¶

  • Blocks are never deallocated — image/vhdx/writer.go:217-218: "A block is never deallocated: writing zeros over a block that is already allocated stores the zeros in the file." Convert writes each range at most once, so conversion is unaffected.
  • The target must be new or zeroed — image/vhdx/writer.go:220-222. The CLI creates it with os.Create.
  • Close only after all writes — image/vhdx/writer.go:228-230. convert.Convert waits for every worker before it returns (convert/convert.go:223), so the CLI keeps the rule; S3 is what a caller that breaks it would see.
  • The log stays empty — image/vhdx/writer.go:62. Fine for a freshly written dynamic image.
  • Small default blocks, because some file systems fill small holes — image/vhdx/writer.go:170-173. The APFS probe in I4 agrees: it filled every gap up to 16 MiB.
