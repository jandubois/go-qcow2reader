S2. The padding guard is broader than the case it means to catch Gemini 3.1 Pro¶
convert/convert.go

// ensureAlignment returns the write length for nr bytes. When Alignment is set
// and this is the last extent of the image, the write length is rounded up to
// the alignment boundary and the padding bytes are zeroed.
func (w *worker) ensureAlignment(nr int, extent image.Extent) int {
	if w.opts.Alignment > 0 && extent.Start+extent.Length == w.conv.size && nr%w.opts.Alignment != 0 {
		alignedLen := align.Up(nr, w.opts.Alignment)

S10. Record why slicing to an aligned address is safe Claude Opus 5¶
convert/convert.go
// is set, the buffer's starting address is aligned to opts.Alignment.
func allocateBuffer(opts *Options) []byte {
	if opts.Alignment == 0 {
		return make([]byte, opts.BufferSize)
	}
	buf := make([]byte, opts.BufferSize+opts.Alignment)
	remainder := int(uintptr(unsafe.Pointer(&buf[0])) % uintptr(opts.Alignment))
	if remainder > 0 {
		buf = buf[opts.Alignment-remainder:]
	}
	return buf[:opts.BufferSize]
}

This is the standard Go direct-I/O idiom and it is correct, because the garbage collector does not relocate heap objects and buf keeps the allocation alive. The unsafe.Pointer to uintptr conversion is also the one direction go vet's unsafeptr check does not police, so nothing would flag it if the assumption changed. One sentence on allocateBuffer tells the next reader the question was asked and answered.

Design Observations ¶

Concerns

  • The direct-I/O contract has three owners and one enforcement point (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash — a working -direct conversion needs an aligned buffer address (owned by allocateBuffer), aligned write offsets and lengths (owned by the source image's extent granularity), and the right open flag on the destination (owned by the caller). Only the first is checked. I3 turns the second into a diagnosable error; a directio.Open helper returning both the file and the matching Options.Alignment would close the third. The richer option is a read-modify-write path for sub-alignment fragments, which would let -direct handle small-cluster images instead of failing cleanly on them.
  • "Direct" means something different on macOS (in-scope) Gemini 3.1 Pro Codex GPT 5.6 Sol Gemini 3.5 Flash — O_DSYNC makes each write synchronous but still routes through the page cache, where qemu-img uses fcntl(fd, F_NOCACHE, 1) on Darwin. The measured speedup is real, so this is about the name matching the behavior, either by switching to F_NOCACHE or by saying what the flag does per platform.
  • No negotiation with filesystems that reject O_DIRECT (future) Codex GPT 5.6 Sol — the author raised this himself: Linux tmpfs rejects O_DIRECT, so making this the default in limactl would break users whose lima home sits on tmpfs. Opening with O_DIRECT and falling back on EINVAL is the usual shape. Worth settling before any caller turns it on by default.
  • Pre-existing: a zero-length extent would hang Convert (future) Claude Opus 5 — convert/convert.go:229 advances start by extent.Length, so a backend returning a zero-length extent with a nil error spins forever inside run rather than failing. No in-repo backend does this, and the merge-base code had the same shape.

Strengths

  • The worker extraction earns its place (in-scope) Claude Opus 5 Codex GPT 5.6 Sol Gemini 3.5 Flash — six setError-and-return sites collapse into plain return err, and zeroExtent / copyExtent / ensureAlignment name the three cases the old nested closure left implicit. I diffed the new loop against the deleted one: it is faithful, including the subtlety that copyExtent takes its extent by value so the caller's start += extent.Length still advances by the original length.
  • Alignment == 0 preserves the old path exactly (in-scope) Claude Opus 5 — allocateBuffer returns a plain make, and ensureAlignment short-circuits on its first conjunct. Existing callers see no change.
  • directio.go records how its platform list was derived (in-scope) Claude Opus 5 — the header comment names the check (O_DIRECT in zerrors_*_*.go), which let reviewers verify the list mechanically instead of guessing. The list is correct; only its negation is wrong.

Testing Assessment ¶

I ran the suite myself at the review SHA on darwin/arm64 with qemu-img and qemu-io 11.0.2 on PATH: go test ./... passes for every package, golangci-lint run (v2.12.2) reports 0 issues, and go vet ./... is clean. Agent worktrees produced the same result, and Codex additionally ran go test -race and drove hack/compare-with-qemu-img.sh against a 1 MiB image. Nothing here reaches real Linux O_DIRECT; every claim about EINVAL rests on the alignment of the write arguments, which I did measure.

Gaps, by risk:

  1. Any Convert call with Alignment > 0. CI never runs it (S1). The padding branch, the write offsets under alignment, and the progress total are all uncovered.
  2. The padding path itself. Every CI image has a GiB-sized virtual size, so nr % Alignment != 0 never holds, including in the new -direct script step (S4). One image with an unaligned virtual size covers S3 and S4 at once.
  3. Non-default cluster sizes with Alignment set. The I3 reproduction took two qemu-img/qemu-io calls and a recording io.WriterAt; a permanent regression test costs about the same.
  4. Cross-GOOS build coverage. I1 has now escaped two rounds because no job builds for the targets on the negated branch of the tag.
  5. Error paths. Short reads, EOF with data, short writes, and a failing worker are untested, including whether the first error is the one returned and whether progress stops.
  6. Filesystems that reject O_DIRECT, and Windows, where -direct does nothing at all.

Documentation Assessment ¶

  • Options.Alignment (convert/convert.go:60) states the power-of-2 and BufferSize constraints. It omits the two that bite: the destination must be opened with directio.Flag, and the source's extent granularity must be at least Alignment (I3).
  • The Convert doc comment (convert/convert.go:166) describes the sparse target contract but not that Alignment can round the output size up (S3).
  • The -direct flag help says "use direct I/O for writing" with no mention that it is synchronous rather than uncached on macOS and inert on Windows.
  • ensureAlignment (convert/convert.go:288) understates its safety argument. Fixing the guard per S2 removes the need for the comment entirely.
  • directio has no package doc comment. Neither do align, convert, or lru, so this matches the repo and is not worth changing on its own.
  • test/units/units.go exports three constants with no doc comments.

Review Process Notes ¶

Skill improvements

  • Forbid editing the code under review. The worktree rule currently bars branches and commits and points scratch work at .scratch/, which leaves editing tracked files allowed by omission. Add: "Do not modify any tracked file in the working tree. To test a hypothesis that needs a code change, describe the change and the expected result in the finding instead of applying it. Any test or build you run must run against the unmodified tree." A reviewer that patches the tree and then runs the suite is reviewing its own edit, and every coverage and test claim it makes afterwards describes code the author never wrote.
  • Check that a benchmark's arms stop at the same completion boundary. When a change ships benchmarks comparing two I/O or concurrency modes, verify both arms wait for the same guarantee before the timer stops: the same flush, the same durability barrier, the same cache state. Look for a shared helper that closes or returns without syncing while one mode's flag or option makes its writes synchronous. An arm that stops earlier is not slower or faster, it is measuring something else, and the deferred work usually lands inside the next iteration.
  • Diff the effective defaults when a convenience constructor is replaced by its explicit form. A refactor that needs one extra argument commonly rewrites os.Create(p) into os.OpenFile(p, flags, mode), or the equivalent in other languages, and silently adopts whatever the author typed for the arguments the convenience form used to supply. Compare each implied argument against the documented default of the call being replaced. These changes are invisible in review because the new line looks deliberate and the old default is not on screen.

Repo context updates

  • [repo] convert.Options.Validate constrains SegmentSize only against BufferSize, never against the source image's cluster size. A caller may therefore pass a legal SegmentSize that is not a multiple of the cluster size, which makes worker segment boundaries land mid-cluster and produces Extent queries at non-cluster-aligned offsets. When reviewing anything that consumes Extent results, check whether the query offsets are cluster-aligned before trusting the returned status and length, and treat a mid-cluster query as an untested path.
  • [repo] qemu-img convert -O raw writes exactly the image's virtual size, while qemu-img convert -O raw -t none -W rounds the output up to the direct-I/O alignment. Comparisons against qemu-img output must therefore match the caching mode, and a size difference between a direct-mode conversion and buffered qemu-img output is expected behavior rather than a defect. hack/compare-with-qemu-img.sh hashes whole files, so it can only compare modes that pad identically.
